# stacks/ = ข้อมูลอ้างอิงและค่าตั้งต้น ไม่ใช่คำตอบตายตัว

การเลือก stack ของทุกโปรเจกต์ให้ใช้สกิล **`/choose-stack`** (ใน Codex ใช้ `$choose-stack`) หรือพูดว่า "ระบบนี้ควรใช้ stack อะไร" สกิลจะ:
1. ไล่ข้อจำกัดของงานนั้นก่อน เช่น ชนิดข้อมูล, ที่ที่ระบบจะรัน, ผู้ใช้, ระดับงาน, ใครดูแลต่อ, งบ
2. หยิบตัวเลือก 2–3 แบบ ซึ่งต้องมีค่าตั้งต้นจากโฟลเดอร์นี้ 1 แบบ และตัวเลือกที่ไม่อยู่ในคลังอย่างน้อย 1 แบบ
3. ค้นข้อมูลล่าสุดจากแหล่งทางการ พร้อม URL และวันที่
4. ให้คะแนน เปรียบเทียบ แนะนำ และบอกเงื่อนไขที่จะทำให้เปลี่ยนคำแนะนำ
5. บันทึก ADR หลังคุณอนุมัติ

ไฟล์ในโฟลเดอร์นี้คือ**ข้อมูลที่เคยค้นไว้แล้ว** เช่น เวอร์ชัน, กับดัก, เหตุผล และ checklist ตามระดับงาน ใช้ให้ agent ไม่ต้องเริ่มค้นจากศูนย์ แต่**ไม่ได้บังคับ**ให้ใช้ตามนี้

| ไฟล์ | สรุปจากงานแบบ | ตรวจล่าสุด |
|---|---|---|
| `hospital-web.md` | ระบบเว็บภายในโรงพยาบาลที่รันบนเซิร์ฟเวอร์เอง | 2026-10-01 |
| `data-dashboard.md` | แดชบอร์ดหรือเครื่องมือวิเคราะห์ข้อมูล | 2026-10-01 |
| `cloud-web.md` | เว็บแอปส่วนตัวบน cloud | 2026-10-01 |
| `mobile-pwa.md` | แอปมือถือ (มี feasibility gate) | 2026-10-01 |
| `video-hyperframes.md` | วิดีโอหรือคอนเทนต์ | 2026-10-01 |

เจองานแบบใหม่ที่น่าจะทำซ้ำ `/choose-stack` จะเสนอให้เพิ่มไฟล์ใหม่ในโฟลเดอร์นี้ ส่วนรอบตรวจรายเดือนจะตรวจเวอร์ชันในทุกไฟล์ให้
