## 1. Evaluation criteria (max 5, checkable)
A repo is only recommended if it passes at least 3, and no idea is adopted without a vault-side test.
1. Adoption and liveness: more than 1,000 stars (or a named vendor owner) AND a commit within 90 days of 2026-10-01. Source: GitHub API `stargazers_count`, `pushed_at`.
2. Evidence of effect: has evals, tests or a published measurement, not only claims. Justification: Anthropic says the verifier is the limiting factor (research/01 S1, S10) and the superpowers ablation below shows some skills add nothing measurable.
3. Context cost is bounded: states a size budget, profiles or on-demand loading. Justification: Claude Code docs say CLAUDE.md under 200 lines and longer files reduce adherence (https://code.claude.com/docs/en/memory, Anthropic, fetched 2026-10-01, T1); Thoughtworks Radar vol. 34 lists agent-instruction bloat under Caution (research/01 S23).
4. Human gate on self-modification: learned rules or skill edits reach trusted files only after human review. Justification: Codex docs: "Keep required team guidance in AGENTS.md or checked-in documentation. Treat memories as a helpful recall layer" (https://learn.chatgpt.com/docs/customization/memories, OpenAI, fetched 2026-10-01, T1).
5. Portable and low supply-chain risk: plain Markdown/SKILL.md that works under both Claude Code and Codex, no mandatory daemon, no unreviewed network install. Justification: core.md hard stops 4 (secrets) and 6 (dependencies); every file can be read before installing.

## 2. obra/superpowers
Repo: https://github.com/obra/superpowers (T2). Author Jesse Vincent. License MIT. Stars 293,501, forks 26,257, pushed_at 2026-09-27, 286 open issues, created 2025-10-09 (api.github.com, fetched 2026-10-01). Latest releases: v6.4.2 (2026-09-25), v6.4.1 (2026-09-19), v6.3.0 (2026-08-12) (api.github.com/repos/obra/superpowers/releases, fetched 2026-10-01).

Structure (README, fetched 2026-10-01): `skills/` with 15 skills (brainstorming, using-git-worktrees, writing-plans, executing-plans, subagent-driven-development, dispatching-parallel-agents, test-driven-development, systematic-debugging, verification-before-completion, requesting-code-review, receiving-code-review, finishing-a-development-branch, using-superpowers, writing-skills, diagnosing-superpowers); `hooks/` (session-start hook + hooks.json); per-harness plugin folders (`.claude-plugin`, `.cursor-plugin`, `.agents/plugins`, `.devin-plugin`, ...); `tests/` (per-harness plugin tests, shell-lint, version-bump, hooks); `evals/` (separate repo, see below). Supports 15+ harnesses including Claude Code, Codex, Cursor, Gemini, Copilot CLI.

How skills chain: seven fixed stages (brainstorm, worktree, plan in 2-5 minute tasks, subagent-driven or inline execution, TDD, review, finish branch). A bootstrap skill `using-superpowers`, injected by the session-start hook, makes the check mandatory: "if there is even a 1% chance a skill applies, invoke it", and "user instructions (CLAUDE.md, AGENTS.md...) take precedence over skills" (raw.githubusercontent.com/obra/superpowers/main/skills/using-superpowers/SKILL.md, fetched 2026-10-01; summary-level, not verbatim).

Mechanics worth knowing (raw SKILL.md on main, fetched 2026-10-01, summary-level):
- `verification-before-completion`: "NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE"; five-step gate: identify command, run, read full output and exit code, verify, then claim; red-flag table ("should work now", "great!" before verifying, trusting agent reports).
- `subagent-driven-development`: fresh implementer per task with only a task brief; two sequential review gates (spec compliance, then code quality) run by the controller, never the implementer; model tiering (cheapest for mechanical tasks, most capable for architecture/final review); implementer status codes DONE / DONE_WITH_CONCERNS / NEEDS_CONTEXT / BLOCKED; fix loop capped at 5 rounds (rounds 4-5 use a stronger model), then controller parks or escalates. Ours is stricter: 2 rounds in core.md, which matches measured pitfall 3.
- `writing-skills`: "NO SKILL WITHOUT A FAILING TEST FIRST". RED: run pressure scenarios without the skill and record rationalizations; GREEN: write minimal skill; REFACTOR: add counters and re-test. Description must start "Use when..." and must NOT summarise the workflow (the agent may follow the description and skip the body); under 500 chars; frequently loaded skills under 200 words.
- `diagnosing-superpowers`: reads session transcripts on disk, produces a report where "every finding cites path:line. No citation, no finding"; may file a GitHub issue only after searching existing issues, showing the exact text and getting explicit human consent.

Testing of skills: README says skill-behaviour tests use an eval harness cloned into `evals/`. That is https://github.com/prime-radiant-inc/superpowers-evals (122 stars, pushed 2026-09-12, T3): "Behavioral eval lab (Quorum) ... drives real coding-agent CLIs (Claude, Codex, Gemini, Kimi...) through a QA agent and grades them on workflow compliance against scenario criteria and deterministic post-checks" (api.github.com, fetched 2026-10-01). obra/superpowers PR #2135 (merged 2026-09-18, https://github.com/obra/superpowers/pull/2135) renamed Drill to Quorum and says live evals run agents in permissive modes so they are not CI-safe; only static gates are.

Update mechanism: via each harness's plugin marketplace (`/plugin install superpowers@claude-plugins-official` for Claude Code; Codex: `/plugins`, search, install). README: updates "are somewhat coding-agent dependent, but are often automatic". Versioning: `.version-bump.json` + `RELEASE-NOTES.md`. Contribution policy: "we don't generally accept contributions of new skills and any updates to skills must work across all of the coding agents we support."

Independent evidence on effect (T3, caution): https://github.com/bartek-890/superpowers-evals, 0 stars, 12-case with/without ablation on superpowers v6.4.2, Claude Sonnet 5.5 as both agent and judge, v2 run 2026-09-29. Claims: superpowers "reliably adds TDD discipline and question-first brainstorming; adds nothing measurable on debugging, verification, or review pushback", at about 1.33x cost per task; the no-plugin baseline already scored 1.00 on debugging, verification, code review. Limits: tiny sample, same model as judge, author admits false positives. Consistent with Anthropic's Mar 2026 note that scaffolding should be removed piece by piece as models improve (research/01 S7).

Ideas worth copying:
1. Retired 2026-10-06: private-history rationalization tables in owned workflow skills. Current changes use Matt's main skills with one central policy and authorized task evidence.
2. `writing-skills` rule: description says WHEN, never the workflow; plus a word budget. Check our three skills' descriptions against it.
3. `diagnosing-superpowers`-style retro: read-only skill that mines Claude Code transcripts of a failed session and cites `path:line` for every finding (feeds section 5).

Risks: (a) bloat/cost: "1% chance" mandatory invocation and a 7-stage chain add tokens and ceremony; our pitfall 7 (process too heavy for a 1-2 person team) applies; third-party ablation shows 1.33x cost. (b) Overlap with the installed Matt Pocock set (grilling vs brainstorming, implement vs executing-plans) would compete for auto-invocation (research/05 section 5 flags this class of conflict). (c) Supply chain: a plugin that injects a session-start hook runs every session and auto-updates; 286 open issues. (d) core.md already has stricter rules (2-round cap, hard stops); wholesale install would conflict (hard stop 9). Verdict: do NOT install wholesale; mine ideas 1-3.

### 5.3 Patterns that avoid noise and drift (synthesis from the table, SYNTHESIS not a single source)
1. Evidence bar: only user corrections, repeated manual work or rework loops count; one-offs wait for a second sighting (claude-retro-skill).
2. Hard caps: at most 3 proposals per run (claude-retro-skill), at most 10 (netresearch); store cap 20 and deletion proposals first (claude-retro-skill); Claude's own 200-line/25KB index cap.
3. Human gate for every write to a trusted file (all three retro tools, claude-reflect, SkillHone local PR, SkillOpt validation gate, dotagents report-first).
4. Promote repeats into enforcement (hook/test), not more prose (claude-retro-skill; Claude docs: hooks apply "regardless of what Claude decides").
5. Cite evidence: `path:line` for every finding (diagnosing-superpowers).
6. Mask secrets before reading transcripts (netresearch `mask-secrets.py`; Codex memories redact secrets).
7. Measure before and after: validation gate (SkillOpt), with/without baseline (skill-creator, bartek ablation).

## 7. Recommendations for our vault (ranked by value / effort)
Value = how much of a measured pitfall or gap it closes; effort S under 1 hour, M half a day. Anything that adds a dependency or edits hooks/CI/tests is a hard stop (core.md 6, 7): it needs your approval first, marked below.

1. **Skill intake checklist + lock file (value high, effort S).** Create `setup/skill-intake.md` with Anthropic's 8-point checklist and the risk table (scripts, network, credentials, MCP, filesystem), a rule "read every file in the skill folder before install; prefer copying the skill over installing a plugin that auto-updates", and a table `setup/skills-lock.md` (name, source URL, commit SHA, date reviewed, reviewer, notes). Add one line to `instructions/core.md` Hard stop 6: "installing a third-party skill = adding a dependency; follow setup/skill-intake.md". Evidence: Snyk 36.82%; Anthropic enterprise checklist; dotagents lock pattern. Then fill the lock for the existing Cloudflare, HyperFrames and Matt sets (SHA = unknown now, record "UNVERIFIED").
2. **Skill lint + drift check (value high, effort S-M).** Add `scripts/lint-skills.mjs` (plain Node, same style as `guardrails/guard.test.mjs`, no dependency) that checks, for each `skills/*/SKILL.md`: `name` equals folder name and matches the spec regex; description 1-1024 chars and begins "Use when"; body under 500 lines; no `http`/`curl`/`fetch` strings unless allow-listed; and compares file hashes between `skills/` and `~/.claude/skills` and `~/.agents/skills` copies (research/05 found drift in 2 skills). Call it at the end of `scripts/sync.ps1` and from the post-commit hook as warn-only. Changes to hooks/scripts need your approval.
3. **Retired 2026-10-06: own `/retro` plus private-note memory loop.** Reuse Matt `retro`; use only authorized task evidence. Environment/policy changes follow core approval rules, and private notes stay unchanged and disconnected.
4. **Retired 2026-10-06: old router/ship rationalization patches derived from personal notes.** Scope, verification and review limits now belong to the central policy; do not copy personal-history traits into skills.
5. **Memory policy paragraph (value medium, effort S).** In `instructions/core.md` (keep under the length budget) add: "Auto memory and Codex memories are recall aids; any rule that must hold goes in checked-in files or a hook; never record secrets or patient data in memory." In `README.md` monthly maintenance block add `/doctor prompt-audit` (Claude Code v2.1.283+) over `~/.claude` and the project instruction files, and a check that `/memory` has no stale or secret-bearing entries. Decision to record in `DECISIONS`-style note: keep Codex memories off (default) until a second project needs it.
6. **"No citation, no finding" in reviewer/researcher agents (value medium, effort S).** In `agents/claude/reviewer.md`, `agents/claude/researcher.md` and the `agents/codex/*.toml` equivalents add: every finding must cite `file:line`, a command output, or a URL with date; uncited items are marked UNVERIFIED. Source: diagnosing-superpowers; our own research rules. Agent files are config: approval needed.
7. **Evals for our three skills (value medium, effort M).** Create `skills/<name>/evals.md` for `new-request`, `ship`, `handoff-pack` with 3-5 prompts each (should trigger, should not trigger, ambiguous), expected behaviour and a pass line, per Anthropic's enterprise guidance; run them once with and once without the skill using the installed `skill-creator` plugin skill, record pass rate and tokens in `skills/CHANGELOG.md`. Re-run on every Claude/Codex model change and quarterly (also as an ablation: if the baseline already passes, shrink or delete the skill, as the superpowers ablation suggests happens). Note existing tests are not edited, new files only.
8. **Version/changelog for skills (value low-medium, effort S).** Add `skills/CHANGELOG.md` and `metadata: version: "x.y"` in each of our SKILL.md frontmatter (allowed by the spec). Bump on change; the post-commit hook can warn if a SKILL.md changed without a version bump.
9. **Credential deny-list cross-check (value medium, effort S).** Compare `scripts/merge-claude-settings.mjs` deny rules with Trail of Bits `claude-code-config` (credentials, SSH keys, cloud configs, shell rc files, package tokens; `enableAllProjectMcpServers: false`) and note gaps in `guardrails/README.md`; do not apply without approval (permission settings are a hard stop). Also state in the README that hooks are not a security boundary against prompt injection.
10. **Context budget for third-party sets (value medium, effort S, already proposed).** In `setup/skills-cleanup-proposal.md` add the Anthropic recall rule: stop adding skills when trigger recall degrades; move Cloudflare (11) and HyperFrames (18) to per-project installs (research/05 section 5 note). Measure with the trigger queries from item 7.

## 8. Do NOT adopt
- obra/superpowers wholesale (and any "install a 7-stage methodology" kit): 1.33x cost, no measured gain on debugging/verification/review in the only (T3) ablation, overlaps Matt's set, auto-updating session hook, conflicts with our 2-round review cap and hard stops. Mine ideas only.
- affaan-m/ECC: 68 agents, 293 skills, 94 commands, 215 open issues, catalog advertised by default; context bloat (criterion 3) and install sprawl.
- claude-mem and episodic-memory: background workers and local services, capture everything by default (our pitfall 5 documents 5 pasted secrets; hospital context raises patient-data risk, hard stop 5). Opt-out tags are not enough.
- Autonomous self-editing loops (Hermes learning loop, SkillOpt-Sleep nightly evolution, any hook that writes to CLAUDE.md/AGENTS.md without review): unreviewed edits to trusted instructions, extra dependencies and API spend; violates criterion 4 and hard stops 6 and 9. SkillOpt is only useful if we first have task sets, which we do not.
- Bulk installs from awesome lists or `skills.sh` popularity: lists do not vet (VoltAgent README discloses no vetting; Composio list is a marketing vehicle); Snyk found 36.82% with issues in public registries.
- Rule-sync tools (rulesync, ruler, agent-rules-sync): a new dependency for something `scripts/sync.ps1` already does; bidirectional real-time sync (3 seconds) risks silent overwrites.
- spec-kit, OpenSpec, BMAD as installed tools: pitfall 7 (process too heavy for 1-2 people); keep only ideas (separate bug and idea paths, archive step).
- planning-with-files: duplicates `STATE.md`/`/handoff-pack`; per-turn re-injection of a file the agent can edit is a prompt-injection surface; benchmark is author-run.
- Karpathy-style single CLAUDE.md (multica-ai/andrej-karpathy-skills, 216,065 stars, pushed 2026-04-20): the README gives no measured results (fetch summary) and our core.md already covers think-before-coding, surgical changes and verifiable goals. Stale (5 months).
- Tiny personal dotagents repos (1-4 stars): T3, no adoption evidence; read for ideas only.
- Anything that installs via `npx`/`pip`/plugin marketplace without first reading the files (hard stop 6).

## 9. Risks you did not ask about
- Retro and memory tools read transcripts: those can hold pasted keys (pitfall 5) or patient data. Mask before mining, keep retro outputs out of git until reviewed, and keep `_inbox/` out of any tool's reach.
- Sources I used are mostly README-level via a summarising fetch tool; star counts and dates are API values from 2026-10-01 but descriptions can contain summarisation errors (one artefact found: "322% passing").
- The superpowers ablation is a 0-star, same-model-as-judge study; do not quote it as proof. It is a reason to measure our own skills, not a verdict on superpowers.
- Adding more rules is itself the main failure mode (instruction bloat); each recommendation above is capped (3 proposals, 20 entries, 200 words) for that reason.
- Licence traps if copying text: trailofbits repos are CC-BY-SA-4.0 or unlicensed; openai/skills and anthropics/skills show no licence field; BMAD and skill-scanner are NOASSERTION.
