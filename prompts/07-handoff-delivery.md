# 07 - ส่งต่องาน ปิดวัน และส่งมอบ

หลักการ: ความจำอยู่ในไฟล์ ไม่ใช่ในแชท commit `wip: handoff` (STATE.md + HANDOFF.md) บน feature branch ก่อนส่งต่อเสมอ ผู้รับต้องตรวจสถานะจริงก่อนทำต่อ เมื่อ skill `/handoff-pack` พร้อมใช้ ให้ลองใช้แทน 07-A และ 07-B (skill: `handoff`)

---

## 07-A ส่งต่อ session ระหว่าง Codex กับ Claude ผ่านไฟล์

**ใช้เมื่อ:** โควตาใกล้หมด (ราว 80%) หรืออยากสลับ agent กลางงาน
**ได้อะไร:** `STATE.md` + `HANDOFF.md` ที่ commit บน feature branch และข้อความสั้นให้วางฝั่งผู้รับ (skill `/handoff-pack` ทำขั้นตอนนี้ให้ทั้งหมด ใช้ prompt นี้เมื่อไม่มี skill)

ฝั่งผู้ส่ง:

```text
เตรียมส่งต่องานให้ agent อื่น ทำตามขั้นตอนของ /handoff-pack: อัปเดต STATE.md และเขียน HANDOFF.md (ที่รากของ repo) แล้ว commit บน feature branch ปัจจุบัน (ห้ามทำบน main/master) ห้ามเก็บไว้ใน Temp หรือ .scratch/ (git-ignored ใช้เก็บหลักฐานก้อนใหญ่เท่านั้น)

ขั้นตอน
  1) commit งานค้างพร้อมไฟล์ทั้งสอง ข้อความขึ้นต้นด้วย "wip: handoff <ticket> — <หนึ่งบรรทัด>" ถ้ามีไฟล์ที่ agent ไม่ได้แก้ ให้ระบุรายการแทนการ commit; push เฉพาะเมื่อ branch ตาม remote อยู่แล้ว
  2) เขียน HANDOFF.md ตามหัวข้อนี้: เป้าหมาย / repo + branch + commit ล่าสุด / ที่เสร็จแล้ว (พร้อมหลักฐาน) / ที่ค้าง / ผลเทสล่าสุด (คำสั่ง + ผลจริง) / สิ่งที่ตัดสินใจไปแล้ว (ห้ามถามซ้ำ) / ข้อห้ามและสิ่งที่ห้ามอนุมาน / ความเสี่ยงที่รู้ / คำสั่งแรกที่ผู้รับควรรัน / สิ่งที่ผู้รับต้อง "ตรวจซ้ำเอง" 3 ข้อ
  3) แยกคอลัมน์ "เชื่อได้ (มีหลักฐานในไฟล์/เทส)" กับ "ต้องตรวจซ้ำ (ข้ออ้างจากความจำของ agent)"
  4) ไม่ใส่ secret ค่าจริง ไม่ใส่ข้อมูลผู้ป่วย ให้บอกแค่ชื่อตัวแปร env
ไม่ทำ: เริ่มงานใหม่ ปรับปรุงโค้ดเพิ่ม merge หรือ push ไป main/master
ให้ STATE.md ชี้ไปที่ HANDOFF.md ด้วย (HANDOFF.md ถูกลบใน commit ที่ปิด ticket)
เสร็จเมื่อ: git status สะอาด, STATE.md และ HANDOFF.md อยู่ใน commit ล่าสุด, และคุณบอกชื่อไฟล์กับ commit SHA ให้ฉันวาง
รายงานสั้น: path ไฟล์ + SHA + ข้อความ 3 บรรทัดที่ฉันควรวางให้ agent ตัวใหม่ + อะไรที่ฉันต้องทำเองก่อนสลับ (เช่น ปิด dev server)
```

ฝั่งผู้รับ:

```text
รับงานต่อจาก agent อื่น อ่าน AGENTS.md, STATE.md และ HANDOFF.md ที่ <path> (branch ที่มี commit "wip: handoff") แล้วตรวจสถานะจริงก่อนลงมือ: git status, branch, git log 10 รายการ, รัน <คำสั่ง verify>
ถือ HANDOFF.md เป็นข้อมูลตั้งต้น ไม่ใช่ความจริง ตรวจซ้ำอย่างน้อย 3 ข้อสำคัญตามที่ไฟล์ระบุ
ห้าม reset, stash หรือทับงานเดิม ถ้ามีไฟล์ที่ไม่รู้ที่มา ให้ถามก่อน
ไม่ทำ: เริ่มแก้ไขก่อนรายงาน
ตอบ: 1) เข้าใจสถานะอย่างไร 2) ข้อไหนใน handoff ที่ตรวจแล้วไม่ตรงกับ repo 3) ขั้นแรกที่จะทำ 4) สิ่งที่ต้องถามฉัน แล้วรอฉันตอบ "ไปต่อ"
เห็นต่างได้: ถ้าเห็นว่าแผนของ agent ก่อนหน้ามีปัญหา บอกก่อนทำต่อ
```

## 07-B ปิดวัน (park) บันทึกให้พรุ่งนี้เริ่มต่อได้

**ใช้เมื่อ:** จบวันหรือต้องไปทำอย่างอื่น ไม่อยากให้พรุ่งนี้ต้องถามว่าทำอะไรไปแล้ว
**ได้อะไร:** STATE.md และ BACKLOG.md ที่อัปเดต พร้อมสรุปสั้นว่าเสร็จอะไร ค้างอะไร ฉันต้องทำอะไร

```text
ปิดวันนี้ ยังไม่ต้อง merge ไม่เริ่มงานใหม่ (ไม่ push ไป main/master; push feature branch ได้เฉพาะเมื่อ branch ตาม remote อยู่แล้ว)
เป้าหมาย: ให้พรุ่งนี้เปิด session ใหม่แล้วใช้ prompt 02-A ต่อได้ทันที

ทำ
  1) ตรวจ git status ถ้ามีงานค้างให้ commit บน feature branch ข้อความขึ้นต้น "wip: handoff <ticket> — <หนึ่งบรรทัด>" พร้อม STATE.md และ HANDOFF.md (ถ้ามีงานค้างที่ต้องส่งต่อ)
  2) อัปเดต STATE.md: งานปัจจุบัน (repo#ticket + branch) / ทำเสร็จวันนี้ / ค้าง (เรียงตามความคุ้มค่า) / ติดอะไร / ขั้นต่อไปขั้นเดียว / สิ่งที่รอจากฉัน / คำสั่งรันระบบ
  3) เพิ่มสิ่งที่ค้นพบแต่ยังไม่ได้ทำลง BACKLOG.md บรรทัดเดียวต่อเรื่อง
  4) หยุด process ที่รันค้างของโปรเจกต์นี้เท่านั้น (dev server, Docker container ที่เราเปิดเอง) แสดงรายการก่อนหยุด
ไม่ทำ: ลบ branch หรือไฟล์ แก้โค้ดเพิ่ม เปลี่ยนแผน

เสร็จเมื่อ: STATE.md ตรงกับ git จริง และไฟล์ STATE.md/BACKLOG.md ถูก commit
เห็นต่างได้: ถ้าเห็นว่าลำดับ "ขั้นต่อไป" ที่ฉันวางไว้ไม่คุ้ม บอกก่อนบันทึก
รายงานสั้นเป็นภาษาไทย: เสร็จวันนี้ / ค้าง / ที่ฉันเท่านั้นต้องทำ / ความเสี่ยงที่ควรรู้ก่อนเริ่มพรุ่งนี้
```

## 07-C ขอรายการเช็กก่อนปล่อยระบบ (release / deploy checklist)

**ใช้เมื่อ:** จะนำระบบขึ้นเซิร์ฟเวอร์โรงพยาบาลหรือปล่อยเวอร์ชันใหม่
**ได้อะไร:** checklist + แผน rollback ที่ตรวจได้ โดยยังไม่รันคำสั่งบนเครื่องจริง (เทียบ skill `engineering:deploy-checklist` ถ้ามี; ถ้าไม่มี skill ให้ใช้ prompt 07-C นี้)

```text
เตรียมเช็กลิสต์ปล่อยระบบ ห้ามรันคำสั่งบนระบบจริง ห้าม merge ห้าม push main/master ห้าม deploy จนกว่าฉันสั่งเป็นข้อๆ

เป้าหมาย: เช็กลิสต์ที่ฉันทำตามได้ทีละข้อ พร้อมแผนย้อนกลับ
ระบบ: <ชื่อ>; ปลายทาง: <เซิร์ฟเวอร์ / cloud ของโรงพยาบาล>; เวอร์ชัน/branch: <release branch หรือ tag>; ระดับงาน: ใช้จริง

บริบท: อ่าน AGENTS.md, RUN.md, ADR, ผลรีวิวล่าสุด, CHANGELOG และ git log ตั้งแต่เวอร์ชันก่อน

ครอบคลุม
  - ก่อนปล่อย: verify เต็มผ่าน (unit, DB, e2e, build), ไม่มี secret ใน repo/ประวัติ, dependency audit, ผลรีวิวความปลอดภัยไม่มีข้อเปิดที่สูง, สำรองฐานข้อมูลและทดสอบกู้คืนได้จริง, migration ทดลองบนสำเนา
  - ขั้นปล่อย: ลำดับคำสั่งที่ต้องรัน (ระบุว่าใครรัน) ตัวแปร env ที่ต้องตั้ง (ชื่อเท่านั้น) และ smoke test หลังปล่อย
  - หลังปล่อย: สิ่งที่ต้องเฝ้าดู 24 ชั่วโมงแรก ใครติดต่อใครเมื่อพัง
  - Rollback: คำสั่งและเวลาโดยประมาณ จุดที่ย้อนกลับไม่ได้ (เช่น migration ลบคอลัมน์) ให้ระบุชัด
  - สิ่งที่เป็นหน้าที่ของไอทีโรงพยาบาล (สิทธิ์เครือข่าย, ไฟร์วอลล์, บัญชีเซิร์ฟเวอร์) แยกเป็นรายการที่ฉันต้องขอ
ทุกข้อต้องมีวิธีตรวจที่ได้ผลเป็นหลักฐาน ข้อที่ยังตรวจไม่ได้ให้ติด "ยังไม่ยืนยัน"
เห็นต่างได้: ถ้าเห็นว่ายังไม่พร้อมปล่อย ให้ฟันธงว่าไม่ควรปล่อยพร้อมรายการที่ขวางอยู่
เสร็จเมื่อ: มีไฟล์ docs/release/<เวอร์ชัน>-checklist.md และ verdict 1 บรรทัด (พร้อม / พร้อมเมื่อแก้ข้อ ... / ยังไม่พร้อม)
รายงานเป็นภาษาไทย: verdict + ข้อที่ขวาง + สิ่งที่ฉันต้องขอจากไอทีโรงพยาบาล + ความเสี่ยงที่ฉันไม่ได้ถาม
```

## 07-D ส่งมอบให้ไอทีโรงพยาบาล (handover)

**ใช้เมื่อ:** ฝึกงานใกล้จบหรือจะโอนระบบให้คนอื่นดูแลต่อ
**ได้อะไร:** ชุดเอกสารส่งมอบ และผลทดสอบว่าคนใหม่ทำตามเอกสารอย่างเดียวแล้วรันกับกู้ระบบได้จริงหรือไม่

```text
เตรียมชุดส่งมอบระบบ <ชื่อ> ให้ผู้ดูแลคนใหม่ (ไอทีโรงพยาบาลหรือคนรับช่วง) ที่ไม่เคยเห็นโปรเจกต์นี้ ยังไม่ต้องแก้โค้ดระบบ

เป้าหมาย: คนใหม่อ่านเอกสารอย่างเดียวแล้ว รันระบบ สำรอง กู้คืน และแก้ของเล็กๆ ได้
ผู้รับ: <บทบาท ระดับความรู้ เช่น เข้าใจ Linux/Docker แต่ไม่รู้จัก Vue>

ทำ: สร้างหรืออัปเดตใน docs/handover/
  1) README: ระบบคืออะไร ใครใช้ วิธีรัน/เทส/build
  2) runbook: deploy, สำรอง, กู้คืน, อาการที่พบบ่อยและวิธีแก้ (เช่น หน้าขาว พอร์ตชน ฐานข้อมูลไม่ขึ้น)
  3) แผนที่สถาปัตยกรรม 1 หน้า + ADR ที่สำคัญ + glossary ศัพท์โรงพยาบาลกับชื่อในโค้ด
  4) รายการที่เก็บ secret และใครถือ (ตำแหน่งเท่านั้น ห้ามใส่ค่าจริง)
  5) สิ่งที่ยังไม่เสร็จ สิ่งที่ตั้งใจไม่ทำ และความเสี่ยงที่รู้ (อ้างจาก BACKLOG.md และ .out-of-scope/)
  6) ข้อมูลผู้ติดต่อเป็นตำแหน่ง/บทบาท ไม่ใส่ข้อมูลส่วนตัวของบุคคล
ไม่ทำ: เขียนเกินจริง ข้อความที่พิสูจน์ไม่ได้ให้ติดป้ายว่า "ผู้พัฒนายืนยันเอง" หรือ "ตรวจแล้ว (อ้างหลักฐาน)" แยกชัด

แล้วทดสอบเอกสาร: ใช้ subagent ใหม่ที่ไม่มีบริบทก่อนหน้า ให้ทำตาม docs/handover/ อย่างเดียวเพื่อรันและกู้ระบบบนสำเนาชั่วคราว (ไม่ใช้ข้อมูลผู้ป่วยจริง) แล้วรายงานทุกจุดที่ติด
เสร็จเมื่อ: subagent ทดสอบผ่าน หรือมีรายการจุดที่ติดพร้อมแก้ไขเอกสารแล้ว
เห็นต่างได้: ถ้าเห็นว่าระบบยังไม่พร้อมส่งมอบ (ไม่มีสำรอง ไม่มีเทส ผู้ดูแลยังไม่ชัด) บอกตรงๆ พร้อมรายการที่ต้องปิดก่อน
รายงานเป็นภาษาไทย: รายการเอกสารที่ได้ / ผลทดสอบโดยคนใหม่ / ช่องว่าง / สิ่งที่ฉันต้องทำเองก่อนส่ง
```
