# stacks/ = ข้อมูลอ้างอิงสำหรับการตัดสินใจ

เริ่มที่ `/ask-matt` (`$ask-matt` ใน Codex) เมื่อยังไม่รู้ flow ใช้ `grill-with-docs` ระบุข้อจำกัด แล้ว `research` ตรวจตัวเลือกจากแหล่งหลัก หากต้องเห็นผลจริงใช้ `prototype` ก่อนบันทึกการตัดสินใจด้วย `domain-modeling`/ADR ดู [prompt 01-D และ 01-E](../prompts/01-start-project.md)

ไฟล์ที่นี่เป็นสูตรและ checklist ที่เคยค้นไว้ ไม่ได้บังคับ stack และไม่ติดตั้งอะไรเอง วันที่ด้านล่างคือวันที่ค้นครั้งก่อน เรื่องเวอร์ชัน ราคา การรองรับและนโยบายต้องตรวจใหม่ตอนตัดสินใจ

| ไฟล์ | งานที่ใช้เป็นข้อมูลตั้งต้น | ตรวจครั้งก่อน |
|---|---|---|
| [hospital-web.md](hospital-web.md) | เว็บโรงพยาบาลบนเซิร์ฟเวอร์เอง ระดับงานและ handover | 2026-10-01 |
| [data-dashboard.md](data-dashboard.md) | dashboard และเครื่องมือวิเคราะห์ | 2026-10-01 |
| [cloud-web.md](cloud-web.md) | เว็บส่วนตัวบน cloud | 2026-10-01 |
| [mobile-pwa.md](mobile-pwa.md) | มือถือ/PWA พร้อม feasibility gate | 2026-10-01 |
| [video-hyperframes.md](video-hyperframes.md) | วิดีโอและ content brief | 2026-10-01 |

ระบุข้อมูล ที่รัน ผู้ใช้ งบ ผู้ดูแล และข้อจำกัดที่ยืนยันก่อนเทียบ 2–3 ทางเลือก แนะนำหนึ่งทางพร้อมเหตุผล แหล่งอ้างอิง และเงื่อนไขที่จะเปลี่ยนคำแนะนำ Stack ที่คุ้นเคยและพอใช้ได้อาจเหมาะกว่าเครื่องมือใหม่

ค่าตั้งต้นส่วนตัวมาจากบทสนทนาที่อนุมัติใน [working style](../instructions/working-style.md) ไม่มีการอ่านบันทึกส่วนตัวจากโฟลเดอร์อื่น
