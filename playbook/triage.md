# คัดแยกงานใหม่: ทำเลย หรือเก็บไว้ก่อน

> ใช้ทุกครั้งที่มีบั๊ก, feedback, ไอเดีย หรือ requirement ใหม่เข้ามา ไล่จากบนลงล่าง **ข้อแรกที่ตรงคือคำตอบ**
> ที่มา: `research/01-agent-workflows.md` §2 (Matt Pocock /triage, Anthropic best practices, Kent Beck, Addy Osmani)

| ระดับ | ประเภท | ทำอะไร | ไปที่ไหน | agent ทำเองได้ไหม |
|---|---|---|---|---|
| **P0** 🔥 | ระบบจริงล่มต่อเนื่อง, ข้อมูลหาย, ข้อมูลส่วนบุคคลหรือผู้ป่วยรั่ว, เสี่ยงข้อมูลผิดคน (error ครั้งเดียวที่ข้อมูลไม่เสียหาย = P2) | หยุดทุกอย่าง กู้ระบบก่อน หาสาเหตุทีหลัง | บันทึกเหตุการณ์ + ticket | วิเคราะห์แบบอ่านอย่างเดียวได้ **แต่คุณต้องอนุมัติทุกการแตะ production** |
| **P1** 🐞 | บั๊กในงานที่กำลังทำอยู่ตอนนี้ | แก้ใน ticket เดิม พร้อม test กันพังซ้ำ ข้อนี้ไม่นับเป็นงานบาน | ticket ปัจจุบัน | ได้ |
| **P2** 🐛 | บั๊กในสิ่งที่ส่งไปแล้ว | ลองทำให้เกิดซ้ำแบบอ่านอย่างเดียว แล้วร่าง ticket ส่วน test ที่ไม่ผ่านจะเขียนตอนลงมือแก้ (`/ship`) | Issue (สร้างหลังคุณอนุมัติ) | ร่างได้เอง สร้าง Issue หลังอนุมัติ |
| **P3** 💬 | feedback: "ยังไม่ตรงกับที่ตกลงไว้" | ถือเป็นบั๊กเทียบกับ spec | ticket ปัจจุบันหรือถัดไป | ได้ |
| **P4** ✏️ | feedback: "อยากให้ทำงานต่างจากเดิม" หรือความสามารถใหม่ที่ต้องใช้บริการภายนอก / secret / มีค่าใช้จ่าย / ข้อมูลส่วนบุคคลใหม่ (เช่น แจ้งเตือน LINE) | เขียนว่าเปลี่ยนอะไร เพราะอะไร กระทบอะไร เช็กข้อมูลล่าสุดของบริการภายนอก แล้วเสนอแก้ spec | ร่าง spec + ticket | **ไม่ได้** ต้องให้คุณตอบ yes ก่อน |
| **P5** 💡 | ไอเดียใหม่, "เพิ่มอันนี้ด้วย", "ทำให้ระดับโลก" | **ห้ามทำกลางคัน** จด 1 บรรทัดลง `BACKLOG.md` แล้วทำงานเดิมต่อ | `BACKLOG.md` | จดได้ทันที ไม่ต้องขออนุมัติ |
| **P6** 🧹 | งานเก็บกวาดที่ agent เห็นเอง | จดพร้อมหลักฐาน ห้ามแก้ใน diff เดียวกัน | `BACKLOG.md` (ประเภท: debt) | จดได้ทันที |
| **P7** 🆕 | โปรเจกต์หรือระบบใหม่ | คุยก่อน: เลือกระดับงาน แล้วซักถามด้วย `grill-with-docs` / `grill-me` ยังไม่เขียนโค้ด | lifecycle ขั้น 0–4 | คุยได้ ห้ามเขียนโค้ด |

> agent ทำเกินที่สั่งเอง (ฟีเจอร์เพิ่ม, refactor ที่ไม่ได้ขอ) ถือว่าผิดกติกา ต้องถอยออกหรือแยกออก แล้วบันทึกไว้ใน "ยังไม่ได้ทำ" ของรายงาน

## BACKLOG ทำงานอย่างไร
- **Inbox = `BACKLOG.md`** ที่ root ของ repo บรรทัดละ 1 เรื่องตามตารางใน `templates/project/BACKLOG.md` agent จดได้ทันที
- **Ticket = GitHub Issues** (ถ้าโปรเจกต์ใช้) agent ร่างได้ แต่สร้างหลังคุณอนุมัติ เรื่องใน BACKLOG ที่ตัดสินใจจะทำ ให้ย้ายไปเป็น Issue
- **คัดแยกสัปดาห์ละครั้งในเวลาที่กำหนด** ไม่ใช่ทุกครั้งที่มีเรื่องเข้ามา
- เรื่องที่ตัดสินใจว่าไม่ทำ ให้บันทึกเหตุผลไว้ ครั้งหน้าที่ไอเดียเดิมกลับมา agent จะเจอคำตอบเก่าแทนที่จะเริ่มถกใหม่

## เหตุผลที่ต้องเข้มกับ P5
จากประวัติแชทของคุณ:
- หน้า login ถูกออกแบบใหม่ 6 รอบ
- RubricLens ได้ระบบที่ไม่ต้องการเพราะคำว่า "ระดับโลก"
- งานค้างใน repo ที่ยังไม่ commit ถึง 30–40 ไฟล์

ทั้งหมดเกิดจากไอเดียที่เข้ามากลางงาน (ดู `me/pitfalls.md`)
