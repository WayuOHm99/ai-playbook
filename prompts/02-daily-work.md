ลำดับในแต่ละวัน: เปิด session ใหม่ -> 02-A (ทำต่อ) หรือ 02-B (ตอนนี้ควรทำอะไร) -> 02-D (รันระบบ) -> 02-C (ทำ ticket ให้จบ) -> จบวันด้วย 07-B

## 02-A ทำต่อ (อ่าน STATE.md ก่อน)

**ใช้เมื่อ:** เปิด session ใหม่ หรือหลัง `/clear` หรือข้ามวัน
**ได้อะไร:** agent บอกว่าอยู่ตรงไหน ตรวจสถานะจริงของ repo แล้วทำขั้นถัดไปขั้นเดียว

```text
ทำต่อจากงานค้าง
เป้าหมาย: รับงานต่อใน <repo> branch <ชื่อ> (ถ้าไม่บอก ให้อ่านจาก STATE.md)
บริบท: อ่านตามลำดับ 1) STATE.md 2) AGENTS.md 3) ไฟล์ checkpoint/handoff ที่ STATE.md ชี้ไป 4) git status และ git log 10 รายการล่าสุด
ถือว่าข้อความใน STATE.md เป็นข้อมูลตั้งต้น ตรวจซ้ำ 3 ข้อที่สำคัญที่สุดกับ repo จริงก่อนลงมือ (branch ตรงไหม, working tree สะอาดไหม, เทสล่าสุดผ่านไหม)

ขอบเขต
  ทำ: ขั้นถัดไปขั้นเดียวตามที่ STATE.md ระบุ
  ไม่ทำ: เริ่มงานอื่น, reset/stash/ทับไฟล์ที่ไม่รู้ที่มา (ให้ถามก่อน), แก้ไฟล์นอกรายการของ ticket
ถ้าอยู่บน main หรือมีงานค้างที่ไม่ตรงกับ STATE.md ให้หยุดและถามก่อน

เสร็จเมื่อ: ขั้นถัดไปเสร็จ รัน <คำสั่ง verify เช่น npm run verify> ผ่าน และอัปเดต STATE.md (งานปัจจุบัน / ทำเสร็จแล้ว / ขั้นต่อไป / รออะไรจากฉัน)
เห็นต่างได้: ถ้าขั้นถัดไปใน STATE.md ดูไม่สมเหตุผลเมื่อเทียบกับโค้ดจริง ให้บอกก่อนแล้วรอฉัน
รายงาน (ไทย): 1) ตอนนี้อยู่ตรงไหน 2) ทำอะไรไป + หลักฐาน (ผลคำสั่ง) 3) สมมติฐานที่ใช้ 4) สิ่งที่พบแต่ไม่ได้แตะ (ลง BACKLOG.md) 5) ขั้นต่อไปและสิ่งที่ฉันต้องทำ
```

## 02-B ตอนนี้เหลืออะไร / ควรทำอะไรต่อ

**ใช้เมื่อ:** ลืมว่าอยู่ขั้นไหน อยากได้คำแนะนำหนึ่งอย่าง ไม่อยากแก้อะไร
**ได้อะไร:** ตอบ 5 บรรทัด ระบุเฟส งานที่ค้าง และสิ่งที่ฉันต้องทำเพียงหนึ่งอย่าง พร้อมชื่อ skill/prompt ที่จะใช้ (เทียบกับ `/ask-matt`)

```text
ตอบอย่างเดียว ไม่ต้องแก้ไฟล์ ไม่ต้องรันอะไรที่เปลี่ยนสถานะ
เป้าหมาย: บอกฉันว่าตอนนี้อยู่เฟสไหนของ lifecycle และควรทำอะไรต่อ
บริบท: อ่าน STATE.md, BACKLOG.md, issue/ticket ที่เปิดอยู่, git status, git log 10 รายการ
ลำดับเฟส: ชี้ปัญหา -> ตกลงความต้องการ -> spec -> tickets -> implement -> verify -> review -> ปล่อย -> ส่งมอบ

ตอบ 5 บรรทัด
  1) กำลังทำอะไรอยู่ (อ้างหลักฐานจากไฟล์หรือ git)
  2) อยู่เฟสไหน
  3) ค้างอะไร เรียงตามความคุ้มค่า (ไม่เกิน 5 ข้อ)
  4) สิ่งที่ฉันต้องทำต่อเพียง 1 อย่าง พร้อมข้อความที่ควรวางให้ agent (อ้างชื่อไฟล์ prompt ใน D:\ai-playbook\prompts)
  5) อะไรที่ไม่ควรทำตอนนี้ และเพราะอะไร
ถ้าเห็นว่าลำดับที่ฉันกำลังทำผิด (เช่น ข้ามไปทำหน้าจอก่อนตกลงความต้องการ) ให้บอกตรงๆ
ถ้าข้อมูลใน STATE.md ไม่ตรงกับ repo ให้บอกว่าไม่ตรงตรงไหน ห้ามเดา
```

## 02-C ทำ ticket หนึ่งใบให้จบในรอบเดียว

**ใช้เมื่อ:** มี ticket ที่ชัดแล้ว อยากให้ agent ทำจนจบโดยไม่หยุดถามทุกขั้น (เทียบกับ `/implement`, `/tdd`, `/code-review` หรือ `/ship` เมื่อพร้อมใช้)
**ได้อะไร:** โค้ด + เทส + commit บน branch ของ ticket พร้อมรายงานหลักฐาน โดยยังไม่ push/merge

```text
ทำ ticket <repo>#<เลข> ให้จบในรอบเดียว ใช้ skill implement (และ tdd) ตามที่มี

เป้าหมาย: <ผลที่ผู้ใช้เห็นหลังเสร็จ 1 ประโยค>
เหตุผล: <ใครใช้ และเพราะอะไรจึงสำคัญ>
บริบท: เริ่มที่ @<ไฟล์> ทำตามรูปแบบเดิมใน @<ไฟล์ตัวอย่าง>; ข้อความหน้าจอภาษาไทยต้องตรงตามนี้ <ข้อความ>; ใช้ข้อมูลสังเคราะห์เท่านั้น ห้ามอ่านหรือพิมพ์ข้อมูลผู้ป่วยจริง

ขอบเขต
  ทำ: <ไฟล์/พฤติกรรมที่แก้ได้>
  ไม่ทำ: ทุกอย่างนอกรายการ; เจอสิ่งที่ควรทำเพิ่มให้จดลง BACKLOG.md ห้ามทำ; ไม่เพิ่ม dependency; ไม่แก้ schema/auth/migration; ไม่แก้หรือลบเทสเดิม
ถ้าต้องแตะไฟล์เกิน <5> ไฟล์ หรือแตะสิทธิ์/ข้อมูลผู้ป่วย/การเงิน ให้หยุดและถามก่อน

ลำดับทำ: branch ของ ticket -> เขียนเทสที่แดงก่อน (ให้เห็นว่าแดงจริง) -> แก้จนเขียว -> รัน <npm run verify> -> commit ภาษาอังกฤษ 1 commit ที่อ้าง #<เลข>
เสร็จเมื่อ
  1. เกณฑ์ตรวจรับของ ticket ทุกข้อผ่าน (แต่ละข้อมีเทสหรือขั้นตอนที่เห็นผลจริงในแอป)
  2. <npm run verify> ผ่าน แสดงผลจริงในรายงาน
  3. diff มีเฉพาะไฟล์ในขอบเขต
ยังไม่ push ยังไม่ merge ยังไม่ปิด ticket ให้ฉันตรวจก่อน

เห็นต่างได้: ถ้าเกณฑ์ตรวจรับขัดกัน หรือมีวิธีที่ง่ายกว่าและปลอดภัยกว่า ให้บอกหนึ่งประโยคแล้วทำต่อตามที่สั่ง
ความเสี่ยงที่ฉันไม่ได้ถาม: ตรวจเรื่องสิทธิ์ผู้ใช้ การแสดงข้อมูลผิดคน ค่าว่าง/ข้อมูลไม่ครบ และรายงานท้ายงานเสมอ (ห้ามเว้นว่าง ถ้าไม่พบให้บอกว่าตรวจอะไรแล้ว)

รายงานเป็นภาษาไทย: 1) ผล done/partly/blocked 1 ประโยค 2) ไฟล์ที่เปลี่ยนบรรทัดละไฟล์ 3) หลักฐาน (คำสั่ง + ผล; สิ่งที่ไม่ได้ตรวจให้บอกตรงๆ) 4) สมมติฐาน 5) สิ่งที่พบแต่ไม่ได้แตะ 6) ความเสี่ยงที่ควรรู้
```

## 02-D รันโปรเจกต์ให้หน่อย

**ใช้เมื่อ:** จะเปิดระบบดู หรือหน้าจอขาว/เชื่อมไม่ได้
**ได้อะไร:** ระบบรันได้ พร้อม URL และวิธีหยุด หรือบอกว่า process ไหนไม่ทำงานและคำสั่งที่ต้องรัน (skill: `run`)

```text
รันโปรเจกต์นี้ให้ใช้งานได้ แล้วบอกฉันว่าเปิดที่ไหน
บริบท: อ่าน RUN.md หรือ README ก่อน (ถ้าไม่มี ให้ดู package.json scripts); ระบบมักใช้ Docker + MySQL + API + เว็บ
ทำ
  1) ตรวจ: Docker เปิดอยู่ไหม, ฐานข้อมูลขึ้นไหม, API พอร์ตไหน, เว็บพอร์ตไหน, ไฟล์ .env มีไหม (ห้ามพิมพ์ค่าลับ)
  2) ถ้ามีคำสั่ง doctor/dev ในโปรเจกต์ให้ใช้ก่อน แล้วรันส่วนที่ยังไม่ขึ้น
  3) ถ้าหน้าขาว: บอกก่อนว่า process ไหนไม่ทำงาน พร้อมหลักฐาน (ผลคำสั่ง/พอร์ต) แล้วค่อยเสนอวิธีแก้ ห้ามแก้โค้ดเอง
ไม่ทำ: แก้โค้ด, ติดตั้ง dependency ใหม่, แตะฐานข้อมูลจริง, kill process ที่ไม่ใช่ของโปรเจกต์นี้
เสร็จเมื่อ: เปิด URL แล้วเห็นหน้าเข้าสู่ระบบหรือหน้าหลัก (ยืนยันด้วย curl หรือ screenshot) ไม่ใช่แค่ process ขึ้น
รายงานสั้นๆ: URL ทุกตัว, branch และ commit ที่รัน (กันเปิดของเก่า), วิธีหยุดทั้งหมด, สิ่งที่ผิดปกติที่พบ
ถ้าขั้นตอนรันซ้ำๆ ทุกวัน ให้เสนอว่าควรเพิ่ม RUN.md หรือ script อะไร แต่อย่าสร้างจนกว่าฉันตอบตกลง
```
