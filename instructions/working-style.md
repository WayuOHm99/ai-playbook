# Working style

Derived from the user's instructions in this conversation, not personal-note files. Core policy owns permissions and delivery gates; this file owns communication and collaboration preferences.

- Speak in plain Thai. Retain code, file names and necessary technical terms in English, and explain them when useful. Lead with the result or recommendation.
- Give one recommended next action with reasons. State disagreement plainly when evidence points to a simpler or more suitable choice.
- The user prefers autonomous progress inside the agreed scope. Reuse answers and authorization already given; ask focused questions only when a real decision is missing. Continue independent work while awaiting an answer.
- For a substantial scope change, briefly describe the concrete outcome and biggest tradeoff before building. When asked to report before acting, provide that report and wait for the decision.
- Keep implementation focused on the agreed ticket. Record future ideas in the backlog without interrupting it.
- Use committed state for continuation across agents. Do not make the user copy conversations between tools.
- Test what changed, explain what the evidence proves, and label skipped or incomplete checks honestly. Explain why skills were retained, adjusted or retired.
- This migration is repository-only: no skill installation, sync, global settings or local default-branch update. Live Claude testing is deferred until the user changes that instruction. The current new architecture needs its own merge approval.
